# 通过 Figwright 获取设计信息

[返回技能入口](skill.md) · [实现与验证](usage-and-validation.md)

## 连接与目标核对

1. 先检查当前 Agent 是否已有 Figwright MCP、CLI 或项目封装工具，读取其实际 schema/help。不要混用其他 Figma 服务的同名接口，也不要硬编码版本、端口、session 或安装路径。
2. 若尚未连接，按照现有 Figwright 安装说明启动读取服务，并在具有目标文件权限的 Figma 会话中运行对应开发插件。仅连接服务不代表能读取目标设计；需要用户手动打开文件/插件时明确指出缺少的步骤。
3. 从当前连接状态选择目标会话，核对文件名、页面、目标节点和预览。插件重启后重新获取 session。记录 URL 提供的 fileKey 与工具实际核实的身份字段，无法核实的字段标记为未验证。

连接只用于读取与导出。不要为取得截图修改原设计；确需临时节点的导出方案须检查其副作用与清理方式。

## 最小采集范围

| 信息 | 用途 |
| --- | --- |
| 节点 ID、类型、父子关系、可见性、顺序 | 建立控件层级与来源映射 |
| 画板尺寸、局部坐标、变换、布局框和绘制边界 | 定位、裁剪、旋转/镜像及资源显示范围 |
| Auto Layout、间距、Padding、对齐、固定/Hug/Fill、约束 | 选择 UMG 容器和尺寸规则 |
| 填充、渐变、描边、圆角、透明度、效果、遮罩 | 原生属性或明确的图层导出决策 |
| 文本、字体、字重、字号、混合样式、换行与行高 | TextBlock/RichTextBlock 与字体资源映射 |
| 图片引用、裁剪、滤镜、组件/实例信息 | 资源绑定与可复用组件识别 |
| 原型动作、组件状态、动画覆盖 | 识别业务事件、动态节点和未支持内容 |
| 完整尺寸参考图、源节点图片/SVG、必要原始图片 | 实现资源与视觉比较 |

Figwright 中常见的读取入口包括 `get_design_context`、`get_node`、`get_motion_context`、`get_reactions`、`save_screenshots`、`save_image_fills`；文件绑定可使用 `use_file`。这些是能力定位提示，调用前以当前工具 schema 为准。

设计上下文可能裁剪字段或去重节点，必要时补读完整节点。确认动画和原型检查覆盖目标子树，不能把未读取到的行为当作不存在。

## 导出与可追溯性

- 保存源快照、节点与资源对应关系、采集时间、导出倍率和参考图。项目已有离线包格式时优先沿用，不为单页转换强制引入新协议。
- 将所需资源保存到本地并验证完整性；稳定命名或内容哈希有助于去重和更新。不要把临时远程 URL 留作游戏运行依赖。
- 原始 image fill 不一定包含裁剪、滤镜、混合和父级效果。需要保留最终外观时导出对应节点，并记录静态化范围。
- 优先按设计比例导出；区分布局框与绘制边界，避免截断越界字形、阴影。保留导出像素尺寸与倍率，不能把补齐后的 PNG 强行缩回小数边界导致二次采样。
- 采集前后核对目标结构和参考图；若设计发生变化，重新取得一致版本，避免拼接不同时间的节点与素材。

如果缺少变换、绘制边界、字体或原始资源，先寻找当前工具支持的补充读取方式。无法取得时列出受影响部分，不根据截图臆造数据，也不把特定工程的 Figwright 补丁视为所有环境的默认能力。
