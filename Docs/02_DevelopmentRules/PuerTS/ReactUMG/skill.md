# Figwright → ReactUMG

根据真实 Figma 信息，在目标 Unreal 工程中实现显式 UMG 控件代码。交付可编辑的 TSX、必要的本地资源、启动接入及与任务范围相符的验证结果。

## 按阶段读取

- 连接、定位设计、读取节点与导出资源：[Figwright 采集](figwright-integration.md)。
- 控件映射、布局、资源接入与验证：[实现与验证](usage-and-validation.md)。

## 执行流程

1. **确认输入与工程**：取得 Figma URL/目标节点和 Unreal 工程位置；检查工程指令、已有 TSX 范例、ReactUMG/PuerTS 版本、类型声明、tsconfig、启动入口和未提交改动。只询问无法从上下文确定的必要信息。
2. **读取真实设计**：发现可用 Figwright 工具和参数，绑定目标会话，读取完整节点、布局规则、样式、文字、资源、原型与动画。保存源快照和参考图；先核对来源，再转换。
3. **制定映射**：按设计关系选择 Layout，区分可编辑文字、图片和复杂静态图层。对无法表达的特性说明处理方式；缺少关键信息时停止相关部分，不猜坐标或用占位素材补齐。
4. **编写组件**：在页面组件中直接声明 ReactUMG 标签、内联 Slot 和事件；属性辅助函数可复用，控件层级保持可见。若用户要直接编辑页面，不交付一个只引用生成组件的薄包装。
5. **接入工程**：导入真实纹理/字体，使用现有编译和加载流程，在正确 world 下挂载组件，明确卸载责任。遵守现有目录与依赖约定，不假设某个插件路径、辅助模块或专用脚本存在。
6. **验证并交付**：检查类型与实际 JS 输出；条件具备时在 UE 中加载本次组件，核对画面和实际交互。提供代码位置、布局选择、静态化内容、测试证据与未完成项。

## 核心规则

- 采用 ReactUMG 原生标签，不输出 HTML/CSS 或把完整 UI 交给通用节点解释器。默认沿用项目的 React.Component/函数组件风格。
- 优先 Overlay、Box、Grid 等有明确布局含义的控件；Canvas 用于确实需要的自由定位。单次 Slot 优先内联，类型由直接父容器决定。
- 参考截图用于验证，不作为整页贴图代替控件转换。保留节点 ID 与资源来源，复杂子树或静态文字光栅化需说明；不静默烘焙交互或动态文本。
- 保留源 Auto Layout 的尺寸与对齐语义；只有固定坐标时不声称已实现响应式布局。
- Figwright 是设计读取端，不是游戏运行依赖。转换可以直接由 Agent 编写 TSX；已有生成器或离线包工具可复用，但不是使用本技能的前提。
- 只修改本任务涉及的代码和资源。重新生成不能覆盖手写业务；原型中的外部操作不能直接当作已授权的业务动作执行。
- 类型通过、UE 运行、视觉阈值、人工接受、Cook/打包是不同结论。验证不了的环节明确标记，不以历史报告替代本次结果。
